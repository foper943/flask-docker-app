# Отчёт о фаззинг-тестировании

**Дата:** 2026-05-17  
**Инструмент:** pytest + requests (tests/fuzzing/fuzz_api.py)  
**Покрытие:** все публичные и защищённые эндпоинты

---

## Методология

Каждый эндпоинт проверялся четырьмя классами пэйлоадов:

| Класс | Примеры | Цель |
|-------|---------|------|
| SQL-инъекции | `' OR 1=1 --`, `'; DROP TABLE users; --` | Проверка параметризованных запросов |
| XSS | `<script>alert(1)</script>`, `<img src=x onerror=...>` | Проверка экранирования вывода |
| Граничные значения | `""`, `None`, строки 65 536 символов, `\x00` | Проверка валидации |
| Неверные типы | числа вместо строк, массивы, булевы | Проверка типовой валидации |

## Результаты по эндпоинтам

### POST /api/auth/register

| Пэйлоад | Результат | Статус |
|---------|-----------|--------|
| `' OR 1=1 --` в email | 400 Bad Request | ✅ Безопасно |
| `<script>alert(1)</script>` в name | 201 (сохранено как текст) | ✅ JSON API не уязвим к XSS |
| `""` в email | 400 Bad Request | ✅ Валидация работает |

## Итоговые выводы

### Защищено ✅
- SQL-инъекции невозможны: все запросы используют параметризацию psycopg2
- XSS нерелевантен для JSON API (экранирование на стороне React)
- Самозапись на сессию к себе заблокирована (422)
- Whitelist-валидация статусов сессии
- JWT-валидация на всех защищённых маршрутах

### Требует внимания ⚠️
- Невалидный формат `scheduled_at` → нужен try/except с возвратом 400
- Очень длинные строки (65 536+ символов) принимаются в `name`/`topic` — рекомендуется ограничение на уровне БД (`VARCHAR(500)`)

### Рекомендации
1. Добавить `CHECK (length(name) <= 200)` на уровне схемы БД
2. Обернуть вставку сессии в try/except с обработкой `ValueError` для `scheduled_at`
3. Добавить rate limiting (flask-limiter) на эндпоинты регистрации и логина

## Запуск тестов

```bash
# Поднять сервер
docker-compose up -d

# Запустить фаззинг
BASE_URL=http://localhost:8080 pytest tests/fuzzing/fuzz_api.py -v

# Только SQL-инъекции
BASE_URL=http://localhost:8080 pytest tests/fuzzing/fuzz_api.py -v -k "sql"
```
